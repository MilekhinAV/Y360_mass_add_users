# Импорт сотрудников и подразделений в Яндекс 360 из XLSX

Скрипт `import_yandex360_users.py` создаёт сотрудников Яндекс 360 из XLSX-файла и при необходимости автоматически формирует иерархию подразделений.

Основной сценарий рассчитан на Windows 10 и Windows 11. Скрипт также работает в macOS и Linux.

## Возможности

- проверка структуры и содержимого XLSX до выполнения изменений;
- создание недостающих подразделений сверху вниз;
- повторное использование существующих подразделений;
- создание сотрудника в последнем подразделении, указанном в строке;
- добавление рабочего телефона, мобильного телефона и дополнительного email;
- пропуск логинов, которые уже существуют в организации;
- обработка постраничных ответов API;
- защита от превышения лимитов API;
- повтор запросов после ошибок `429`, `500`, `502`, `503` и `504`;
- безопасный режим `--dry-run` без создания объектов;
- итоговый CSV-отчёт по каждой строке.

Скрипт предназначен только для создания сотрудников. Данные существующих сотрудников он не изменяет.

## Состав проекта

- `import_yandex360_users.py` — основной скрипт;
- `new_mail_users_import_template.xlsx` — шаблон импорта;
- `requirements.txt` — зависимости Python;
- `test_import_yandex360_users.py` — локальные тесты;
- `README.md` — инструкция.

## Требования

- Windows 10/11, macOS или Linux;
- Python 3.10 или новее;
- доступ к `https://api360.yandex.net`;
- учётная запись администратора организации Яндекс 360;
- OAuth-токен с необходимыми правами;
- идентификатор организации `ORG_ID`.

## Создание OAuth-приложения

Если подходящее OAuth-приложение и токен уже есть, перейдите к разделу «Установка в Windows».

1. Откройте <https://oauth.yandex.ru/>.
2. Авторизуйтесь под учётной записью администратора организации Яндекс 360.
3. Нажмите **Создать**.
4. Выберите **Для доступа к API или отладки**.
5. Укажите понятное название приложения.
6. Добавьте права:
   - `directory:read_users`;
   - `directory:write_users`;
   - `directory:read_departments`;
   - `directory:write_departments`.
7. Создайте приложение.
8. Откройте его общие сведения и скопируйте `ClientID`.

Права на группы, реестр общих ящиков и чтение организации этому скрипту не требуются.

### Получение OAuth-токена в Windows

Откройте PowerShell и выполните:

```powershell
$clientId = Read-Host "ClientID OAuth-приложения"
Start-Process "https://oauth.yandex.ru/authorize?response_type=token&client_id=$clientId"
```

В открывшемся браузере:

1. проверьте запрашиваемые права;
2. подтвердите доступ;
3. скопируйте выданный OAuth-токен;
4. сохраните его в защищённом месте.

Токен выдаётся от имени текущей учётной записи. Эта учётная запись должна обладать административными правами в нужной организации.

> Не публикуйте OAuth-токен, не отправляйте его в переписке и не добавляйте в Git. Файлы `.env`, отчёты и рабочие XLSX с персональными данными также не следует помещать в публичный репозиторий.

## Установка в Windows

### 1. Установите Python

Скачайте актуальную версию Python 3 с <https://www.python.org/downloads/windows/> и установите её.

После установки откройте PowerShell и проверьте Python:

```powershell
py --version
```

Команда должна показать Python 3.10 или новее.

### 2. Откройте каталог проекта

Скачайте репозиторий через **Code → Download ZIP**, распакуйте архив и откройте полученный каталог в Проводнике.

Щёлкните правой кнопкой мыши по свободному месту в каталоге и выберите **Открыть в терминале**. Убедитесь, что в открытом PowerShell находятся файлы:

```powershell
Get-ChildItem
```

В списке должны присутствовать `import_yandex360_users.py`, `requirements.txt` и `new_mail_users_import_template.xlsx`.

### 3. Создайте окружение и установите зависимости

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активировать виртуальное окружение не требуется: далее используется Python непосредственно из `.venv`.

## Подготовка XLSX

Откройте `new_mail_users_import_template.xlsx` и заполните лист `Шаблон`. Не переименовывайте фиксированные колонки `A–M`.

1. `last_name` — фамилия, обязательное поле;
2. `first_name` — имя, обязательное поле;
3. `middle_name` — отчество;
4. `login` — логин, обязательное поле;
5. `password` — пароль;
6. `must_change_password` — требование сменить пароль;
7. `position` — должность;
8. `gender` — пол;
9. `birthday` — дата рождения в формате `YYYY-MM-DD`;
10. `language` — язык;
11. `work_phone` — рабочий телефон;
12. `mobile_phone` — мобильный телефон;
13. `personal_email` — дополнительный контактный email.

С колонки `N` начинаются уровни подразделений:

- `N` — первый уровень;
- `O` — второй уровень;
- `P` — третий уровень;
- последующие колонки — следующие уровни.

Пример пути:

```text
Школы → Школа №1 → Класс 5А
```

‼️ Каждый следующий уровень должен быть заполнен только после предыдущего. Конструкция `Школы → пустая ячейка → Класс 5А` считается ошибкой.

Если все уровни подразделений пустые, сотрудник создаётся в корневом подразделении с ID `1`.

### Правила заполнения

- `login`, `first_name`, `last_name` и `password` обязательны;
- логины внутри одного XLSX не должны повторяться;
- существующий в организации логин будет пропущен;
- пустой `password` не передаётся в API;
- `must_change_password` принимает `true/false`, `1/0` или `да/нет`;
- телефоны рекомендуется хранить в Excel как текст, особенно если используется знак `+`;
- дата рождения должна иметь формат `YYYY-MM-DD`;
- уровни подразделений должны идти без пропусков.

Поле `personal_email` создаётся как дополнительный контакт сотрудника:

```json
{
  "type": "email",
  "value": "mail@ya.ru",
  "label": "Personal"
}
```

Это контакт в профиле, а не алиас почтового ящика. Письма на этот адрес не будут автоматически поступать в ящик Яндекс 360.

## Пробный запуск в Windows

Сначала выполните проверку без изменений:

```powershell
.\.venv\Scripts\python.exe import_yandex360_users.py new_mail_users_import_template.xlsx --dry-run
```

Если токен и ID организации не заданы заранее, скрипт запросит их:

```text
OAuth-токен:
ID организации:
```

При вводе OAuth-токен не отображается на экране.

Режим `--dry-run` выполняет только GET-запросы: получает существующие подразделения и логины, но ничего не создаёт. OAuth-токен и `ORG_ID` всё равно необходимы.

После завершения проверьте итог в терминале и созданный CSV-отчёт.

## Реальный импорт в Windows

Если пробный запуск завершился без ошибок, выполните ту же команду без `--dry-run`:

```powershell
.\.venv\Scripts\python.exe import_yandex360_users.py new_mail_users_import_template.xlsx
```

Не закрывайте PowerShell до появления итоговой статистики и пути к CSV-отчёту.

## Итоговый отчёт

Рядом с исходным XLSX создаётся CSV-файл:

- `yandex360_dry_run_report_ГГГГММДД_ЧЧММСС.csv` — пробный запуск;
- `yandex360_import_report_ГГГГММДД_ЧЧММСС.csv` — реальный импорт.

Статусы строк:

- `planned` — сотрудник будет создан при реальном запуске;
- `created` — сотрудник создан;
- `skipped` — логин уже существует;
- `error` — API вернул ошибку или не удалось подготовить подразделение.

Если API вернул `x-request-id`, он записывается в последнюю колонку отчёта. Этот идентификатор потребуется при обращении в поддержку Яндекс 360.

Коды завершения:

- `0` — обработка завершена без ошибок создания;
- `1` — отдельные строки завершились ошибкой;
- `2` — не пройдена проверка файла, параметров или стартовых запросов к API.

## Частые ошибки

### Команда `py` не найдена

Python не установлен или Windows не видит Python Launcher. Установите Python с <https://www.python.org/downloads/windows/>, закройте PowerShell и откройте его повторно.

### Ошибка `No module named openpyxl`

Зависимости установлены не в то окружение. Выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### HTTP 401

OAuth-токен недействителен, отозван или введён с ошибкой. Получите новый токен и повторите запуск.

### HTTP 403

У OAuth-приложения нет необходимого права либо учётная запись не обладает административными полномочиями.

Проверьте четыре права приложения и после изменения прав получите новый OAuth-токен.

### Некорректные заголовки `A–M`

Заголовки первого листа отличаются от структуры шаблона. Используйте исходный `new_mail_users_import_template.xlsx` и не переименовывайте первые 13 колонок.

### Между уровнями подразделения есть пустая ячейка

Удалите разрыв в иерархии. Все уровни от `N` до последнего заполненного должны идти подряд.

### Найдены два подразделения с одинаковыми `name` и `parentId`

В организации существуют два разных подразделения с одинаковым названием под одним родителем. Скрипт не выбирает одно из них автоматически, поскольку сотрудник может попасть в неправильную ветку.

Проверьте подразделения в панели администратора Яндекс 360. Случайный дубликат следует переименовать или удалить только после проверки вложенных подразделений и сотрудников.

### Логин уже существует

Это не критическая ошибка. Строка получает статус `skipped`, а обработка остальных сотрудников продолжается.

## Безопасность

- не передавайте OAuth-токен другим лицам;
- не указывайте токен в командной строке через `--token`, поскольку он может попасть в историю команд;
- всегда начинайте с `--dry-run`;
- проверяйте `ORG_ID` перед реальным импортом;
- не публикуйте заполненный XLSX и CSV-отчёты с персональными данными;
- не добавляйте `.env` и каталог `.venv` в Git.

Рекомендуемые записи для `.gitignore`:

```gitignore
.venv/
.env
__pycache__/
*.pyc
yandex360_*_report_*.csv
```

## Используемые методы API

- `GET /directory/v1/org/{orgId}/departments` — получение подразделений;
- `POST /directory/v1/org/{orgId}/departments` — создание подразделения;
- `GET /directory/v1/org/{orgId}/users` — получение сотрудников;
- `POST /directory/v1/org/{orgId}/users` — создание сотрудника.
